# Make Knowledge Cards

把一篇文章转成一组自足的知识卡片，让读者不回头翻原文也能真正学会其中的知识。

## Inputs

接受两种输入，先判断属于哪一种：

| 输入类型 | 判断依据 | 处理方式 |
|---|---|---|
| 粘贴的文本 | 用户直接在对话中给出正文 | 直接使用消息中的文本 |
| 本地文件 | 用户给出 `.md` / `.txt` 路径 | 用 Read 读取完整内容 |

输入不符合要求时，直接说明不支持并请用户换形式提供：

- 只给了 URL / 网页链接 → 说明不支持抓取网页，请用户粘贴正文或另存为 TXT/MD
- 给了 `.pdf` / `.docx` / `.epub` → 说明不支持该格式，请用户转成 TXT 或 Markdown
- 要求导出 Anki 牌组（`.apkg` / CSV 导入格式）→ 说明本技能只产出卡片内容，不做 Anki 导出
- 要求做成网页 / App / 图形界面 → 说明本技能只产出卡片文本

文件为空、乱码、或明显不是文章（如纯日志、纯代码、纯表格数据）时，说明原因并停止，不要硬造卡片。

## Workflow

1. **通读全文**，理解主题、结构、论证或步骤脉络。
2. **抽取知识点**：找出文中真正承载知识的内容单元。优先取这些：
   - 定义、概念、术语
   - 原理、机制、因果关系
   - 分类、对比、边界条件
   - 可操作的方法、步骤、参数
   - 有说服力的数据或结论
3. **合并与去重**：同一知识点只保留一张卡。同一内容的换种说法、重复强调、同义例子，合并进一张卡。
4. **定数量**：目标 5~8 张。
   - 知识点充足 → 取最重要、最独立的 5~8 个，宁可少而精，不要为凑数拆散同一知识点。
   - 知识点不足 5 个（文章本身很短）→ 输出实际数量，并说明"原文知识点有限，仅生成 N 张"。**绝不编造**。短到只剩一两百字时，允许低至 2~3 张，但仍需保证每张都是独立知识点。
5. **排序**：按原文逻辑顺序或由基础到进阶排列，让卡片连起来能复现原文的知识主线。
6. **写卡片**：按下面的格式逐张输出。

## 卡片格式

每张卡片固定四段，缺一不可：

```
### 卡片 N：<标题>

**核心知识**
<一句话点明这张卡要记住的东西，不超过 40 字，可独立成立>

**简明解释**
<2~4 句话，说清"是什么/为什么/怎么用"。只讲一个知识点，不牵扯其他卡片的内容>

**例子或自测**
<二选一，优先选更能体现该知识点的那种：
 - 例子：原文中的实例，或基于原文知识的直接应用，需具体到可复现
 - 自测：一个能检验是否真正理解的问题，附简短答案>
```

## Hard Rules

- **一卡一知识点**：一张卡只讲一件事。发现写了两件事，拆卡或删掉次要的那件。
  - 判据：如果卡片标题里出现"和""与""及"连接的两个对象，且两者可以各自独立成卡，就拆开。
  - 例外：原文本身就把它们作为一条"做法"提出（如"HTML 设 no-cache，资源设长 max-age"），且拆开后单张卡片不再成立，则保留为一张。
- **只提取原文知识**：内容必须是原文真正包含的。
  - 可以用自己的话重述、可以用原文的例子。
  - 不要引入原文没有的概念、数据、案例、延伸结论。
  - 不要写"建议进一步学习……""推荐阅读……"之类的补充。
- **不编造**：不确定的、原文说得含糊的、自己推断出来的，一律不写进卡片。宁可少一张。
- **不凑数**：原文只能支撑 3 张就写 3 张。
- **去重**：输出前自查一遍，两张卡的核心知识不能是同义。
- **语言跟随原文**：原文中文就用中文，原文英文就用英文；术语保留原文用法，不要替换成自造的译名。
- **卡片自足**：不出现"如上文所述""见前文"这类依赖原文上下文的指代。
- **标题写短语不写句子**：标题是一个名词短语（如"ETag 精度高于 Last-Modified"），不要写成带主谓宾的整句，也不要写成疑问句；问题留给自测环节。

## Output

- 先给一行概览：`共 N 张卡片 | 主题：<一句话主题>`
- 再依次输出卡片，卡片之间空一行
- 卡片输出完成后，另起一段列出**卡片清单**（仅标题，便于快速浏览）：
  ```
  卡片清单
  1. <标题>
  2. <标题>
  ...
  ```
- 用户要求保存文件时，写入用户指定路径（未指定则放在当前工作目录），文件名默认 `<主题>-知识卡片.md`，内容为"概览 + 卡片 + 清单"。只写 `.md` 或 `.txt`，不生成其他格式。
